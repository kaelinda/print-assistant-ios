# 工具首 Tab 与组内排序设计

## 背景

当前应用底部导航的顺序为“最近、文件、工具”，工具页的三个分组和组内顺序直接写在 `ToolsView` 中，用户无法调整高频工具的位置。本次改动将工具入口提升为首个 Tab，并提供符合 iOS 习惯的组内排序能力。

## 目标

- 底部 Tab 顺序调整为“工具、最近、文件”，搜索继续作为独立按钮。
- 每次冷启动默认进入“工具”页，方便用户直接开始处理任务；不额外持久化上次 Tab，避免从旧任务上下文恢复到不可预期的页面。
- 工具分组保持现有分类，不允许跨组移动。
- 用户可以在独立的排序页中拖拽调整每个组内的工具顺序。
- 排序结果持久化，应用更新后能够兼容新增、删除或下线的工具。
- 保持工具主页现有的玻璃卡片视觉，不把主页重构成系统 `List`。

## 交互设计

工具主页右上角显示“调整顺序”。普通状态下工具行仍然是直接进入对应流程的按钮。点击“调整顺序”后通过现有 `NavigationStack` 推入 `AppModel.Route.toolOrderEditor`，进入独立的“调整工具顺序”页面：

- 顶部标题为“调整工具顺序”，副文案为“仅调整组内顺序”。
- 页面使用分组 `List` 和系统拖拽手柄，三个组仍按“文档、打印与证件、更多 PDF”显示。
- 每组只允许在自身范围内移动；组标题和组之间的边界固定。
- 右上角“完成”保存顺序并返回工具主页；系统返回、导航栏返回按钮和交互式侧滑返回都会丢弃临时排序，不写入存储。
- 编辑页使用系统 `List` 的原生拖拽手柄和排序语义；每一行提供稳定的可访问标签与“可拖移排序”提示，VoiceOver 用户通过系统排序操作完成移动。原生手柄不依赖自定义 identifier。
- 保存后通过已有的 transient message 给出轻量反馈，不阻断后续操作。

## 数据模型与持久化

工具由稳定的 `ToolID` 标识，显示文案、图标、颜色和路由由 `ToolCatalog` 注册表派生，避免把闭包或展示对象写入存储。每个 `ToolGroup` 持有默认 ID 数组和固定归属。工具的本地化标题与副标题继续使用现有字符串键，路由闭包只存在于目录的运行时映射中。

`ToolOrderStore` 使用 UserDefaults key `print-assistant.tool-order` 保存带版本号的 Codable 载荷。载荷形状固定为 `{ "version": 1, "groups": { "documents": ["pdfTools", ...], ... } }`，读取旧值、解码失败或版本不支持时回退到默认顺序；当前版本不做跨版本迁移，未来版本通过显式迁移函数升级。

- 读取时过滤未知 ID、去重，并按照默认数组补回缺失的工具。
- 过滤时同时校验工具的固定组归属；组结构变化时只影响对应组，不把工具搬到另一个组。
- 没有存储值或载荷损坏时使用默认顺序。

这保证新版本增加工具后老用户可以看到新入口，同时保留已有排序偏好。

## 实现边界

- 不改变二级“证件工具”页面内部的功能顺序；本次排序只针对工具主页的三个组。
- 不引入第三方依赖或新的动画框架。
- 复用现有 `GlassActionRow`、`GlassCard` 和 `GlassTabBar` 的设计语言。
- 由于排序页使用系统 `List`，只在排序页采用系统编辑交互，主页仍保持当前滚动卡片布局。
- `AppModel.selectedTab` 的初始值改为 `.tools`；该值只在当前进程内变化，重新启动时仍回到工具页。

## 验证

- 单元测试覆盖默认顺序、未知 ID 过滤、重复 ID 去重、缺失工具补回、固定组归属、保存读取和损坏/未知版本回退。
- UI 测试验证工具 Tab 是首个 Tab、默认启动进入工具页、排序入口可打开、排序页按组显示、系统返回不保存、完成后保存并在下一次启动恢复；测试通过稳定的行 identifier/label 验证编辑页契约。原生排序手柄和 VoiceOver reorder action 由系统 `List` 提供，不通过脆弱的私有控件 identifier 断言。
- 运行构建、相关单元测试和现有 UI 回归测试。
